# macOS에서 소스로 설치하기

**저장소 클론 → Go 빌드 → 샘플 실행 → 내 세션 연결** 순서로 사용합니다. 현재 확인한 환경은 macOS Apple Silicon과 Go 1.26.4입니다.

## 1. Git과 Go 준비

터미널에서 다음 명령을 한 줄씩 실행합니다.

```sh
git --version
go version
```

- Git이 없거나 Command Line Tools 설치 안내가 나오면 [Git의 macOS 설치 안내](https://git-scm.com/install/mac)를 따라 설치합니다. Apple Command Line Tools로 Git을 설치할 수 있습니다.
- Go가 없으면 [Go 공식 설치 안내](https://go.dev/doc/install)에 따라 Mac용 Go를 설치하고 터미널을 새로 엽니다. 이 프로젝트에서 확인한 버전은 **Go 1.26.4**입니다.
- 명령을 찾을 수 없다는 오류가 계속되면 설치와 PATH를 먼저 확인하세요. 두 명령이 버전을 출력한 뒤 다음으로 진행합니다.

기본 빌드·관찰에는 Git과 Go만 필요합니다. Python, Node.js, Make, Docker, 데이터베이스, 모델 API 키, 하네스 설정은 필요하지 않습니다. 처음 빌드할 때 Go 의존성을 내려받으므로 인터넷 연결이 필요합니다. 실제 대화를 보려면 Codex가 이미 기록한 대화 파일이 있어야 합니다.

## 2. 저장소 클론과 빌드

프로젝트를 둘 상위 폴더에서 시작합니다. 터미널에 `cd `를 입력한 다음 해당 폴더를 끌어 놓고 Return을 누르면 이동할 수 있습니다.

```sh
git clone https://github.com/kochungcheon/agent-observer.git
cd agent-observer
go build -trimpath -o bin/agent-observer ./cmd/agent-observer
./bin/agent-observer version
```

명령은 한 줄씩 실행하고 오류가 나면 멈추세요. 이미 `agent-observer` 폴더가 있다면 내용을 지우지 말고 다른 상위 폴더를 선택하세요. 빌드는 성공하면 보통 아무 메시지 없이 끝나고 `bin/agent-observer`를 만듭니다. 마지막 명령이 버전과 플랫폼을 출력하면 빌드·실행이 확인된 것입니다. 소스 빌드에서는 버전이 `dev`로 나오는 것이 정상입니다. Make가 설치되어 있다면 `make build`도 같은 빌드 명령을 실행합니다.

이후 모든 명령은 **클론한 `agent-observer` 폴더 안에서** 실행합니다. 실행 파일에 UI가 들어 있어 프런트엔드 설치나 별도 서버는 필요하지 않습니다. 미리 빌드된 파일을 다운로드하는 배포 방식과 달리, 이 경로에는 배포자 Developer ID 서명·공증을 설치 필수 단계로 요구하지 않습니다. OS 경고가 발생하면 성공으로 간주하거나 보안 기능을 끄지 말고 오류를 확인하세요.

## 3. 계정 없이 샘플 보기

```sh
./bin/agent-observer demo
```

출력된 로컬 URL을 브라우저에서 엽니다. 기본값은 `http://127.0.0.1:8767/?demo=1`입니다. **합성 샘플** 표시를 확인하세요. 실제 대화를 읽거나 모델을 호출하지 않습니다. 그룹을 접고 펼치거나 메시지 연결선을 눌러 볼 수 있습니다.

서버가 실행되는 동안 터미널이 입력을 받지 않는 것은 정상입니다. 종료하려면 **그 터미널에서 Ctrl-C**를 누릅니다. 포트 사용 중 오류가 나오면 기존 서버를 임의로 종료하지 말고 다음처럼 다른 포트로 실행하고 **새로 출력된 URL**을 여세요.

```sh
./bin/agent-observer demo --port 18767
```

## 4. 내 대화 파일 연결

샘플 화면에서 **모든 세션 → 내 세션 연결하기**를 선택하면 같은 서버에서 연결할 수 있습니다. 빈 화면으로 시작하려면 샘플 서버를 Ctrl-C로 종료한 뒤 다음 명령을 실행하세요.

```sh
./bin/agent-observer
```

기본 포트를 사용할 수 없다면 `./bin/agent-observer --port 18767`로 실행합니다. 설정 파일, `init`, 훅, 추가 로그인이 없어도 기본 관찰은 동작합니다.

1. Finder에서 **Shift-Command-G**를 누르고 `~/.codex/sessions`를 입력합니다. Codex에 `CODEX_HOME`을 별도로 설정했다면 그 경로 아래 `sessions`를 사용하세요.
2. 보고 싶은 대화의 날짜 폴더에서 **메인 대화의 `.jsonl` 파일 하나**를 선택합니다. 폴더 자체나 다른 대화·하위 작업자 기록을 대신 선택하지 마세요. 파일명의 세션 ID로 구분하기 어렵다면 아래 선택적인 목록 기능을 사용하세요.
3. **Option-Command-C**로 파일 경로를 복사합니다.
4. Observer의 **내 세션 연결하기**에 경로를 붙여 넣고 **연결**을 누릅니다. 입력칸에는 따옴표나 `file://` 없이 복사한 경로를 그대로 사용합니다.
5. 대화의 실행 흐름과 **실시간 연결됨 · SSE** 표시를 확인합니다. 이후 실제로 기록되는 이벤트가 있을 때 새 카드가 생깁니다.

원본 대화 파일은 수정하지 않습니다. 기록이 비어 있으면 그래프도 비어 있을 수 있습니다. 화면에서 수동 연결한 세션은 서버를 종료하면 사라지므로 다음 실행 때 다시 연결하세요. 파일을 직접 지정해 시작할 수도 있습니다.

```sh
./bin/agent-observer --source "/absolute/path/to/rollout.jsonl"
```

직접 파일을 찾기 어렵다면 [전체 안내의 선택적인 세션 목록 설정](getting-started.md#optional-saved-settings)을 참고하세요. 목록 탐색은 사용자가 켰을 때만 동작하며 기본 설치 요건이 아닙니다.

## 막혔을 때

| 증상 | 확인할 내용 |
| --- | --- |
| `repository not found` 또는 인증 요청 | 자리 표시자를 실제 공개 저장소의 HTTPS 주소로 바꿨는지 확인하세요. 아직 공개되지 않은 주소는 클론할 수 없습니다. |
| `destination path ... already exists` | 기존 폴더를 지우지 말고 다른 상위 폴더에서 클론하세요. |
| `go.mod file not found` | `cd agent-observer`로 저장소 루트에 들어왔는지 확인하세요. |
| 모듈 다운로드 오류 | 인터넷·조직 네트워크 설정과 오류 문구를 확인하세요. 첫 빌드는 의존성을 내려받습니다. |
| `./bin/agent-observer: No such file or directory` | 저장소 루트인지, Go 빌드가 성공했는지 확인하세요. |
| 포트 사용 중 | `--port 18767`처럼 다른 포트를 선택하고 출력된 URL을 여세요. |
| 세션 목록이 비어 있음 | 기본은 자동 탐색하지 않습니다. `.jsonl` 하나를 직접 연결하세요. |
| 세션 연결 실패 | 절대 경로인지, 파일이 존재하고 읽을 수 있는지, 서버가 실행 중인지 확인하세요. |
| 명령이 끝나지 않음 | 서버 명령은 정상입니다. `version`이 멈췄다면 Ctrl-C로 중단하고 OS 알림·오류를 확인하세요. |
| `본문 미제공` | 원본이 본문을 제공하지 않은 것입니다. 기본 관찰 설치가 네이티브 암호화 메시지를 복원하지는 않습니다. |

## 업데이트와 제거

업데이트할 때는 실행 중인 Observer를 Ctrl-C로 종료하고, 직접 수정한 파일이 있는지 `git status`로 확인한 뒤 `git pull --ff-only`와 위 Go 빌드 명령을 실행합니다. 충돌이나 로컬 수정 경고가 나면 파일을 강제로 덮어쓰지 마세요.

기본 사용은 백그라운드 서비스를 설치하지 않습니다. 제거하려면 서버를 종료하고, 필요한 작업을 보존한 뒤 클론한 폴더를 지우면 됩니다. 선택적으로 만든 설정·훅·메시지 저장소는 [전체 안내](getting-started.md)를 따라 별도로 정리하세요. Codex 원본 대화 파일은 삭제 대상이 아닙니다.
